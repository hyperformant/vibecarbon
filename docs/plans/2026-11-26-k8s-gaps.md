# Kubernetes gaps (Part A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the three k8s gaps on every provider: true comments about the apiserver address (A1), `status` that lets a new operator address through first (A2), and CI/CD on k8s that works by pull, with nothing at GitHub ever connecting to a cluster (A3).

**Architecture:** A1 is comments plus a guard test. A2 adds one fan-out helper beside `ensureOperatorIpAccessWarn` and calls it from `status` before its remote reads. A3 moves what `carbon/.github/workflows/deploy.yml` did onto the operator's machine (`configure cicd <env>`, which the operator-IP gate already lets in), gives each cluster its own read-only deploy key and, for a private image, a `read:packages` pull Secret, then deletes the workflow and every GitHub copy the CLI used to make for it.

**Tech Stack:** Node ESM CLI, vitest, `kubectl` through `runKubectlWithRetry`, `gh` through `runCommandAsync`, Flux v2.10.0, `node:crypto` ed25519.

**Spec:** `docs/specs/2026-11-26-k8s-everywhere-design.md`, section "Part A: the three gaps".

**Delivery:** one PR per gap, as the spec orders. PR 1 = Task 1 (A1). PR 2 = Task 2 (A2). PR 3 = Tasks 3 to 7 (A3). Each PR branches from main, gets a whole-branch review, and is squash-merged as soon as its required checks are green (Brandon's standing decision).

## Global Constraints

- Conventional Commits.
- Commit with `git commit -F <msgfile> -- <paths>` (pathspecs only, `git add` new files first).
- Never `--no-verify`.
- No `!:` or BREAKING CHANGE footers (use a "Compatibility note" paragraph in the body).
- Every commit message ends with the line `Claude-Session: https://claude.ai/code/session_01SK1vqQLM9B9SaK3Q9Hxjgo`.
- No em or en dashes in user-facing copy (help, prompts, docs).
- CLI voice lowercase, friendly, says why.
- One dotenv dialect (`util.parseEnv` + `formatDotenvLine`, never hand-parse .env).
- Never read or print `tests/.env.e2e`.
- Recursive greps over `tests/` or the repo root pass `--exclude='.env*'`.
- No real cloud servers or real GitHub repos in any task (real-server proof later, outside this plan).
- `rm -rf carbon/dist` after any local template build.
- No `lint --write` on files the task does not change.
- Tests per AGENTS.md (unit via vitest; the exact command is named per task).
- From the spec: no provider token at GitHub, and 22 and 6443 never wider than the operator CIDRs. No retry ladders: a failure gets a root cause.
- Secrets ride stdin or the environment, never argv (docs/security.md section 3). The deploy key's private half and the pull token never touch disk.

## Review Focus

1. `status -json` under `CI=true` (the e2e runner, scripts): the runner's address is never saved to `.vibecarbon.json` or pushed to a firewall. Test in Task 2.
2. A new address with several environments, an HA one and one on another provider: every environment's firewall gets it (both sides of the HA one), each with its own provider's token, and one failure does not stop the rest. Test in Task 2.
3. An operator without admin rights on the repo: GitHub refuses the deploy key; `configure cicd` says who can fix it and leaves the cluster's current key and Secret working. Test in Task 4.
4. A cluster write that fails after the new deploy key was added: the new key is removed at GitHub, and the old key and old Secret keep Flux pulling. Test in Task 4.
5. `configure cicd` run before the first build has published the image: the anonymous probe sees no package, so it asks for a token, and a good token is stored even though the package does not exist yet. Test in Task 5.
