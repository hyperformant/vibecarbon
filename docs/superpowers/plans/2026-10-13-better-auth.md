# Better Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Authentication runs in-process in the Hono app on Better Auth (Postgres via Drizzle), and the GoTrue service, its Kong/Traefik routes, its Helm values and every CLI/e2e dependency on it are removed.

**Architecture:** `carbon/src/server/auth/` builds one `betterAuth()` instance on the Drizzle adapter (uuid ids, tables in `public`), mounted at `/api/auth/*`. Sessions are same-origin HttpOnly cookies (no Bearer tokens in the SPA). The Hono session middleware calls `auth.api.getSession({ headers })` and sets `c.get('user')` / `c.get('session')`. Super-admin = `user.role === 'super_admin'` (admin plugin). MFA = twoFactor plugin (TOTP + backup codes); "AAL2" = this session completed a TOTP/backup-code verification, tracked on the session row. Impersonation = admin plugin. Emails (verification, password reset, magic link) are sent by the app's existing SMTP mailer. The super-admin is ensured by the app at startup from `ADMIN_EMAIL`/`ADMIN_PASSWORD` (no CLI tunnel, no SQL insert into an auth schema). Account lockout stays ours (existing `failed_login_attempts` SQL functions) via a `hooks.before` on `/sign-in/email`.

**Tech Stack:** `better-auth` (+ `better-auth/plugins`: `admin`, `twoFactor`, `magicLink`), Drizzle (from the Drizzle plan), Hono, React 19, Vitest, real Postgres for auth integration tests.

**Spec:** `~/.claude/plans/glowing-bubbling-papert.md` ("Auth: Better Auth"; parity list; "Better Auth validates sessions against the DB unless cookieCache is on (enable it)"). Inventory of everything GoTrue touches: `.superpowers/sdd/gotrue-inventory.md` (read it before planning work in any task).

**Depends on:** the Drizzle data layer plan (`adminDb`, `withUserDb`, `app.user_id()`, Drizzle schema). Execute after it.

## Global Constraints

- Better Auth config: `basePath: '/api/auth'`, `baseURL: env.SITE_URL`, `secret: env.BETTER_AUTH_SECRET` (min 32 chars), `advanced.database.generateId: false` with uuid columns defaulting to `gen_random_uuid()` (ids stay uuid so existing `uuid` FKs keep working), `session.cookieCache: { enabled: true, maxAge: 300 }`, `emailAndPassword: { enabled: true, minPasswordLength: 8, requireEmailVerification: <true only when SMTP is configured> }`, `trustedOrigins: [SITE_URL]`.
- Social providers: Google and Microsoft only (what `vibecarbon configure` offers). The client's GitHub/Apple/Discord buttons and the `GITHUB_ENABLED`/`APPLE_ENABLED`/`DISCORD_ENABLED` env vars are deleted (they were never wired to anything). OAuth redirect URI becomes `<SITE_URL>/api/auth/callback/<google|microsoft>`; update the text `vibecarbon configure` shows.
- Magic link stays (plugin `magicLink`), gated by `MAGIC_LINK_ENABLED` (default true).
- Super-admin: admin plugin with `adminRoles: ['super_admin']`, `defaultRole: 'user'`. Every `app_metadata.role === 'super_admin'` check becomes `user.role === 'super_admin'` through ONE helper `isSuperAdmin(user)` in `carbon/src/server/lib/auth.ts`.
- RLS: `app.user_id()` is set from the Better Auth session user id by `withUserDb` (unchanged contract). `is_super_admin()` SQL reads `select role = 'super_admin' from "user" where id = app.user_id()`.
- AAL: `session.twoFactorVerified boolean default false` (additional session field), set true only by an `after` hook on the twoFactor verify endpoints for that session. `requireAal2` passes when MFA is globally off, or when `session.twoFactorVerified` is true. Users without 2FA enrolled cannot pass `requireAal2` while MFA is globally on (same as today).
- ForwardAuth (Traefik → `/api/_internal/verify-role`): the `vc-admin-token` cookie now carries the Better Auth session token; verify-role validates it via `auth.api.getSession` with a synthesized cookie header. Cookie flags and domain rules unchanged (HttpOnly, parent domain from SITE_URL, 1 h). The SPA session cookie is still never accepted by verify-role.
- User profile fields: `name` (was `user_metadata.full_name`), `image` (was `user_metadata.avatar_url`), additional field `onboardingCompleted boolean default false`.
- FKs that referenced `auth.users(id)` now reference `"user"(id)` with the same ON DELETE behavior.
- Secrets: `create.js` generates `BETTER_AUTH_SECRET` (64 chars). `JWT_SECRET`, `ANON_KEY`, `SERVICE_ROLE_KEY` remain only for the Supabase services still running until the removal plan (Kong, Studio, Realtime); the app must no longer read any of them.
- No Supabase/GoTrue vocabulary in new code, copy, env names or test names.
- Template uses npm. Conventional commits, pathspec commits, never `--no-verify`.

## Review Focus

1. A user with 2FA enrolled signs in by magic link or OAuth (Better Auth does not gate those by 2FA by default): their session must be aal1 (`twoFactorVerified` false), so `requireAal2` routes (DELETE /me, owner promotion, delete org, billing checkout/portal, impersonation) return 403 `mfa_required`. Test in Task 3.
2. Lockout: 5 failed passwords lock the account/IP pair; a locked account gets 429 even with the right password; success clears failures. Test in Task 2.
3. Impersonating another super-admin or yourself is refused; stopping restores the admin's session; an impersonated session cannot reach admin routes. Test in Task 5.
4. Session cookie not sent to subdomain services (n8n, Grafana): only `vc-admin-token` is parent-domain scoped. Test in Task 5 (cookie attributes).
5. Startup admin bootstrap is idempotent and never resets an existing admin's password; a non-admin with the ADMIN_EMAIL gets promoted (same as today's SQL merge). Test in Task 2.
