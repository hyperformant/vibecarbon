# Linode k8s and k8s-ha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Linode runs vibecarbon's `k8s` and `k8s-ha` modes with the same lifecycle as Hetzner and DigitalOcean (deploy, scale, backup, destroy, restore, failover).

**Architecture:** A new Pulumi program `linode-k8s.js` modelled on `digitalocean-k8s.js` (VPC, tag-free Cloud Firewall attached at create, metadata-driven boot scripts). It differs where Linode differs: fixed VPC addresses, the reserved IP given to the master at create, and k3s's embedded cloud controller instead of a Linode CCM. Storage is the Linode Block Storage CSI driver with our own tagged StorageClass. Destroy's DigitalOcean-only backstop becomes a provider capability that Linode also has. The DigitalOcean and Hetzner boot scripts are NOT touched. Deduplicating the metadata-driven scripts waits for Vultr, the third instance.

**Tech Stack:** Node ESM CLI, `@pulumi/linode` 6.9.0, k3s, bash cloud-init (no apt, no jq), vitest.

**Spec:** No separate spec. The facts this plan argues from were measured on real Linode servers on 2026-11-07 (probe `vcprobe-36ab05`, every resource deleted) and are restated in each task where they bind. Seam inventory: every file:line below was read on origin/main 8e23ee0f.

## Global Constraints

- Linode facts (measured, binding):
  - VPC exists in every `LinodeProvider.REGIONS` entry except `us-east` and `us-southeast`.
  - Instance interfaces: legacy config interfaces, public first then VPC: `interfaces: [{ purpose: 'public' }, { purpose: 'vpc', subnetId, ipv4: { vpc: '<addr>' } }]`, with `interfaceGeneration: 'legacy_config'` set explicitly (new accounts default to Linode Interfaces). eth0 = public + default route, eth1 = VPC, MTU 1500.
  - `10.0.1.1` is the VPC gateway and is rejected. Fixed VPC addresses start at `.2`.
  - Cloud Firewall filters VPC traffic: VPC peers need explicit ACCEPT rules for TCP, UDP and ICMP from the VPC subnet.
  - A second public IPv4 on a running Linode is refused without a Support ticket. A reserved IP works only as the instance's sole IPv4, given at create (`Instance.ipv4s: [reservedIp.address]`).
  - Metadata: `TOKEN=$(curl -sS -X PUT -H "Metadata-Token-Expiry-Seconds: 3600" http://169.254.169.254/v1/token)`, then `GET /v1/instance` and `/v1/network` with header `Metadata-Token: $TOKEN`; text lines `id: <n>`, `ipv4.public: <ip>/32`, `ipv4.vpc: <ip>/32`. Rate limit 10 requests per window.
  - CSI: release asset `https://github.com/linode/linode-blockstorage-csi-driver/releases/download/v1.1.5/linode-blockstorage-csi-driver-v1.1.5.yaml`; Secret `kube-system/linode`, key `token`; tolerates every taint; volume tags come from StorageClass parameter `linodebs.csi.linode.com/volumeTags` (comma-separated, no spaces); minimum size 10Gi; volume labels are `pvc-<16 hex>`.
- No Linode CCM. Linode k3s servers run WITHOUT `--disable-cloud-controller` and WITHOUT `--kubelet-arg=cloud-provider=external` (k3s's embedded controller initializes nodes and keeps the pre-seeded provider id). They keep `--kubelet-arg=provider-id=linode://<id>`, `--disable servicelb`, and every other common server flag.
- Default sizes (mine to choose; same class in both HA regions): master and worker `g6-standard-2` (2 vCPU, 4 GB), db `g6-standard-1` (1 vCPU, 2 GB). Primary k8s cluster is about US$60 per month plus volumes and the reserved IP (US$0.0068/h).
- Boot scripts: no `apt`, no `jq`, no `docker` (`tests/unit/deploy/k3s-no-apt.test.ts`). Parse metadata with `sed`.
- Labels: Linode firewall labels cap at 32 characters and instance labels at 50; use linode.js's existing squeeze helpers (linode.js:135-169), never new ones.
- Repo rules: dotenv only through `formatDotenvLine`; `.vibecarbon.json` only through `updateProjectConfig`; commit with pathspecs; never `--no-verify`; conventional commits with no `!:` or BREAKING footer and no attribution lines; no em dashes and no emoji in user-facing copy.
- Tasks 1-6 touch no real servers and dispatch no workflows. Never dispatch a publish or mirror workflow by hand. If a step needs a published image or a public ghcr package that does not exist yet, stop and report it.

## Review Focus

1. Destroy after a deploy that failed partway (master created, cluster never ready): the reserved IP, VPC, firewall and SSH key must still be removed by name or address, and leftover CSI volumes found by project tag. Test in Task 4.
2. Scaling the master to another type replaces the instance: the reserved IP must move to the replacement, which needs the old instance deleted first. Test in Task 2 (`deleteBeforeReplace` and `ipv4s`).
3. `applyOperatorCidrs` on Linode rewrites only TCP rules whose ports are exactly `'22'` or `'6443'` (linode.js:1274-1288): the program's SSH and API rules must use those exact strings, and the VPC accept rules must survive a rewrite. Test in Task 2.
4. A k8s deploy to `us-east` or `us-southeast` must stop before any resource is created, naming the reason and a region that works. Test in Task 6.
5. A worker the autoscaler creates must join the VPC and the firewall, or it can never reach the master. Test in Task 3.
